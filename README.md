# site-templates

网站制作模板集。每个模板是一个独立、可直接跑起来的小项目，放在 `templates/` 下按编号管理。

---

## 模板索引

| 编号 | 模板 | 适用类型 | 技术栈 | 状态 |
| :-: | --- | --- | --- | :-: |
| 01 | [教程型文档站](templates/01-vitepress-docs-site/) | 教程站、使用手册、帮助中心、内部知识库、课程学习路径、选型对比站 | VitePress + Markdown | 可用 |

**使用方法**：进入模板目录 → 读它的 `README.md` → 照着 `GUIDES/` 填内容。

## 分类体系

模板按「**信息架构类型**」分类，不按技术栈分类。技术栈会变，信息结构不会——读者带着目的来找东西的路径才是稳定的。

| 分类 | 适用类型 | 特征 | 已收录 |
| --- | --- | --- | :-: |
| **A. 多章节文档** | 教程站、产品手册、内部知识库、课程路径 | 三段式侧边栏，线性 + 检索混合 | 01 |
| B. 场景手册 | 运维手册、应急处置、常见问题库 | 按「问题」组织而非按「工具」 | — |
| C. 参考手册 | API 参考、参数手册、命令速查 | 高密度表格 + 搜索优先 | — |
| D. 对比选型 | 方案对比、工具评测、选型指南 | 横向对照表为主 | — |
| E. 展示型 | 作品集、产品落地页 | 视觉驱动，非文档结构 | — |
| F. 应用型 | 需要后端、登录、数据库 | 超出静态站范围 | — |

**E 和 F 不打算收录。** 这两类超出了「静态模板」能解决的范围，列在这里是为了说明边界。

### 编号规则

`NN-<技术栈>-<形态>`

例：`01-vitepress-docs-site`、`02-vitepress-api-reference`。

序号一旦分配不再变更——别人会引用这个编号。分类调整用移动 + 追加说明，不改历史编号。

## 收录标准

一个东西要成为这里的模板，需要同时满足：

1. **能直接跑起来** —— clone 后 `npm install && npm run dev` 有内容，不是空壳
2. **结构和说明分离** —— 有独立的 `GUIDES/` 或等价文档说明怎么用
3. **填了示例内容** —— 只有空占位符的不收，示例本身就是文档的一部分
4. **构建通过** —— 提交前实跑一次构建

不满足的归为「草稿」，先放本地。

## 目录结构

```
   └─ 01-vitepress-docs-site/
      ├─ README.md              模板自己的说明
      ├─ GUIDES/                怎么用这份模板
      ├─ docs/                  站点源码
      └─ package.json
```

## 通用约定

所有模板遵守同一条约定：**配置与内容分离，说明与骨架分离。**

| 约定 | 含义 |
| --- | --- |
| 配置集中 | 站点配置只有一个文件，改导航不碰内容 |
| 说明独立 | 使用说明放 `GUIDES/`，不塞进站点页面里 |
| 骨架带类型标注 | 空白处标注「该写什么内容」，不是纯占位符 |
| 标签齐全 | `package.json` 的 `keywords` 写明适用类型，便于检索 |
