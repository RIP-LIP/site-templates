# 示例：自托管手册

用 `templates/01-vitepress-docs-site` 模板填出来的**成品站**。目的是回答一个模板 README 回答不了的问题——**填完到底长什么样**。

| | |
| --- | --- |
| 主题 | 自托管服务（Docker / Compose / restic） |
| 套用模板 | [`templates/01-vitepress-docs-site`](../../templates/01-vitepress-docs-site/) |
| 页面数 | 7 个（首页 + 6 篇） |
| 性质 | **内容全部为可核验事实**，不是虚构示例 |

---

## 这个示例证明了什么

| 证明的事 | 怎么看 |
| --- | --- |
| 三段式能装下真实内容 | 侧边栏的 上手 / 场景 / 原理 三段 |
| 概念页和实操页是两种骨架 | 对比 [`写在开头`](docs/intro.md) 和 [第1章 装 Docker 引擎](docs/start/chapter1.md) |
| 场景页的「先手动再自动化」纪律 | [自动备份到异地](docs/lab/backup.md) 的第 4、6 节 |
| 速查表能独立于正文被引用 | [附录 A 命令速查表](docs/appendix/appendix-a.md) 被另外四页链过去 |
| 内容可以不依赖时效性数据 | 全文没有「已有 XX 万星标」这类会过期的数字 |

---

## 关键取舍

写这个示例时刻意避开了三件事：

1. **不编造数字。** 教程类内容里最容易过期的就是「社区有多活跃」，示例里一个都没有。
2. **不做假成功路径。** 每一章的「验证」小节给的都是能真正失败判定的检查，不是「看到输出即成功」。
3. **不给占位页。** 7 个页面全部有完整可读内容——模板里的占位符全部替换掉了。

---

## 本地运行

```bash
npm install
npm run dev
```

## 目录

```
docs/
├─ index.md              首页：Hero + 六宫格 + 章节总表 + 场景矩阵 + 更新记录
├─ intro.md              概念页：写在开头
├─ start/
│  ├─ chapter1.md        实操页：安装类
│  └─ chapter2.md        实操页：运维 + 故障排查类
├─ lab/
│  └─ backup.md          场景页
├─ build/
│  └─ chapter1.md        原理页
└─ appendix/
   └─ appendix-a.md      速查表
```

与模板骨架的差异只有三处：没有 `<!-- 类型：xxx -->` 标注（写完删掉了）、没有 `【】` 占位符、`config.mts` 里的占位替换成了真实值。
