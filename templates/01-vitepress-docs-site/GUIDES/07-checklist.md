# 07 · 发布前检查清单

逐条核对，不要跳。每条都写明**怎么验**和**不通过时改哪里**。

---

## 一、构建层

- [ ] `npm run build` 无报错
  验：命令行最后一行是 `build complete`
  错因：见 `GUIDES/04` 的模板语法陷阱（`{{ }}` 冲突）

- [ ] 构建无警告堆积
  验：输出里没有大量 `is not loaded, falling back to txt`
  说明：这是未标注语言的代码块提示，不影响构建，但应补上语言标注

- [ ] `description` 已替换
- [ ] `base` 与实际部署路径一致
  验：项目页必须是 `/仓库名/`，根路径才是 `/`
- [ ] `footer.copyright` 已替换
- [ ] `socialLinks` 和 `editLink` 的仓库地址已替换（没有就注释掉）
- [ ] 顶栏 `nav` 每一项都能打开
- [ ] 每个侧边栏条目都有对应文件存在
  验：`npm run build` 不报死链；或对照下面的脚本

## 三、死链检查

站内链接**一律不带 `.html` 后缀**。写死后缀的，一改 `cleanUrls` 就全炸。

手动检查：

```bash
# 构建后检查有没有指向不存在页面的链接
# 先看产物里实际存在哪些页面
ls docs/.vitepress/dist/**/*.html

# 提取所有站内链接，逐个对照
grep -roh 'href="/[^"]*"' docs/.vitepress/dist | sort -u
```

自动检查（可选）：

```bash
npm i -D linkinator
npx linkinator docs/.vitepress/dist --recurse --silent
```

锚点也要验。中文标题的锚点里空格会变 `_`：

```markdown
## 5. 常见问题     →  #_5-常见问题
```

## 四、三处导航一致性

章节信息出现在三个地方，**改一处必须同步另两处**：

- [ ] 顶栏 `nav` 覆盖了所有段落
- [ ] 侧边栏 `sidebar` 列出了所有页面
- [ ] 首页「内容结构」总表与实际章节一致

最常见的事故：侧边栏加了新页，首页总表忘了更新，读者从首页看不到它。

---

## 五、内容层

- [ ] 所有 `【】` 占位符已替换
  验：`grep -rn '【' docs --include=*.md` 结果为空

- [ ] 所有 `<!-- 类型：xxx -->` 填写指引已删除
  验：`grep -rn '类型：' docs --include=*.md` 结果为空

- [ ] 骨架里的示例内容已替换
  验：逐页扫一遍，别留「示例文字」

- [ ] 没有时效性数据裸奔
  查找：版本号、星标数、日期、「最近」「目前」这类词
  处理：加具体日期，或删掉

- [ ] 破坏性操作都有警告
  查找：`rm `、`delete`、`drop`、`rmtree`
  要求：附近有 `::: warning` 或 ⚠️ 标记

- [ ] 速查表带「是否改动数据」列
- [ ] 所有外部链接可访问（抽查 5 个）
- [ ] 所有图片有 `alt`

## 六、写作纪律

- [ ] 概念页有「不划算的部分」一节
- [ ] 实操页有「验证」一节
- [ ] 场景页有「先手动跑一次」和「加失败告警」两节
- [ ] 排障给的是顺序，不是散装技巧
- [ ] 没有「众所周知」「不言而喻」「随着……的发展」
- [ ] 没有自我标榜句（「我们只讲 X 不讲 Y」「本项目坚持……」）

最后一条是硬性要求。**没有实证的能力声明不如不写。** 需要列缺口时用「TODO：待补充」显式标出，而不是含糊填充。

## 快速命令汇总

```bash
# 占位符残留
grep -rn '【' docs --include=*.md
grep -rn 'TODO' docs --include=*.md

# 填写指引残留
grep -rn '类型：' docs --include=*.md

# 模板语法冲突
grep -rn '{{' docs --include=*.md

# 写死的 .html 链接
grep -rn '\.html' docs --include=*.md

# 破坏性命令
grep -rn -E '\brm -|drop |truncate' docs --include=*.md

# 完整重建
rm -rf docs/.vitepress/dist docs/.vitepress/cache && npm run build
```
