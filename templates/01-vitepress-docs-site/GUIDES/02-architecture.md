# 02 · 框架布局与信息架构

这份文档回答两个问题：**站点由哪些部分组成**，以及**内容怎么切成章节**。

---

## 一、技术组成

全站只有两层可写代码，其余都由 VitePress 提供：

```
docs/
├─ .vitepress/
│  ├─ config.mts        ← 站点唯一配置源（导航/侧边栏/页脚/搜索全在这）
│  └─ theme/
│     ├─ index.ts       ← 主题入口，3 行，引入默认主题 + CSS
│     └─ custom.css     ← 换肤只改这个文件
├─ public/              ← 原样拷贝的静态资源（logo、favicon、图片）
└─ **/*.md              ← 页面内容
```

关键设计：**页面文件里不写任何布局信息**。一共有三处例外，全部是显式声明：

| 声明方式 | 出现在哪 | 作用 |
| --- | --- | --- |
| `layout: home` | 首页 frontmatter | 启用首页布局 |
| `sidebar` | 配置里按路径前缀挂载 | 左侧导航树 |
| `nav` | 配置里 | 顶部主导航 |

好处：改导航不用碰内容文件，改内容不会意外破坏导航。

---

## 二、路由规则

路由由文件路径直接决定，**不需要写任何配置**：

| 文件 | 访问路径 | 产物文件 |
| --- | --- | --- |
| `docs/index.md` | `/` | `dist/index.html` |
| `docs/guide/intro.md` | `/guide/intro` | `dist/guide/intro.html` |
| `docs/howto/scenario-1.md` | `/howto/scenario-1` | `dist/howto/scenario-1.html` |

三条实践规则：

1. **站内链接写无后缀路径**（`/guide/intro`），VitePress 自动转成 `.html`。
2. **不要手写 `.html` 后缀**，`cleanUrls` 改了之后全站链接会集体失效。
3. 页面内锚点用中文标题自动生成：

   ```markdown
   ## 5. 常见问题
   ```
   锚点是 `#_5-常见问题`（数字前的空格变 `_`，中文保留）。

## 三、三段式信息架构

模板的核心。每一段对应一类读者，读者知道自己是谁，直接进对应段。

```
上手篇 guide/       ──► 写给「我要把东西跑起来」的人 · 按顺序读 · 入门顺序
场景篇 howto/        ──► 写给「我遇到了具体麻烦」的人 · 按需检索 · 先查这里
原理篇 internals/    ──► 写给「出故障了想自己查」的人 · 选读 · 出事再读
参考篇 reference/    ──► 写给「现在就要抄」的人 · 随时查 · 不读只看
```

### 为什么是这三段

| 段 | 读者的真实问题 | 组织方式 | 失败时的样子 |
| --- | --- | --- | --- |
| 上手篇 | 「从哪开始？」 | 线性顺序，有前置依赖 | 乱序就装不上 |
| 场景篇 | 「我这个问题怎么解？」 | 按处境索引，无依赖 | 找不到对应条目 |
| 原理篇 | 「为什么会这样？」 | 按机制，跨场景 | 记不住知识点 |
| 参考篇 | 「那条命令是什么来着？」 | 按用途查，无解释 | 翻不到就放弃 |

**四段之间靠链接互相跳转，不复制内容。** 上手篇末尾指向场景篇，原理篇开头指向它解释的那个场景。

### 段数可以调整

- 只有 5 页内容：砍掉原理篇，保留 上手 / 场景 / 参考
- 内容是纯概念（没有操作）：砍掉上手篇，保留 原理 / 参考
- 只有一个长篇：不需要分段，用单侧边栏

**但不要在内容不足时硬凑三段。** 空段比没有段更糟——读者点进去发现是空的。

## 四、侧边栏设计

侧边栏按**路径前缀**挂载，不同目录挂不同的树：

```ts
sidebar: {
  '/guide/':     [ /* 上手篇的导航 */ ],
  '/howto/':     [ /* 场景篇的导航 */ ],
  '/internals/': [ /* 原理篇的导航 */ ],
  '/reference/': [ /* 参考篇的导航 */ ],
}
```

三条设计纪律：

### 1. 分组标题带 emoji，且默认展开

```ts
{ text: '📦 第一阶段', collapsed: false, items: [ ... ] }
```

理由：侧边栏可能长达 40 项，读者靠**图标**定位比逐行读文字快。`collapsed: false` 保证所有内容可见——需要滚动，但不会有内容「藏着」。

### 2. 顶层用「写在开头 / 索引」，不要直接堆章节

每个段的第一项固定是一个总览页（`intro` / `index` / `overview`），读者进来先有全局观感，再决定往哪钻。

### 3. 侧边栏 ≠ 首页目录表 ≠ 顶部导航

三者职责不同，不能互相复制：

| 位置 | 回答什么 | 数量级 |
| --- | --- | --- |
| 顶部 nav | 我要去哪一段 | 3~5 项 |
| 侧边栏 | 这一段里按什么顺序读 | 全文 |
| 首页目录表 | 全站有什么、进度如何 | 全部章节一行一个 |

## 五、导航数量参考

| 项 | 建议 | 超出后的症状 |
| --- | --- | --- |
| 顶部 nav | 3~5 | 挤成两行、英文缩写放不下 |
| 侧边栏顶层分组 | 1~3 | 分组内没有归属感 |
| 侧边栏单组条目 | ≤ 20 | 需要滚动才能看完一组 |
| 章节数 | ≤ 15 | 读者失去进度感，改用场景篇组织 |
| 首页六宫格 | 正好 6 | 多于 6 个卡片会挤成两行 |

这些是**经验值不是硬限制**。超过 15 章时，优先考虑把「原理篇」合并进「上手篇」的对应章节，而不是加更多分段。

---

## 六、导航与首页必须一致

三处都列了章节，**改一处就要同步另两处**。发布前用检查清单核对（`GUIDES/07`）。

最常见的错误：侧边栏加了新页，首页目录表忘了更新，读者从首页看不到这篇新页存在。
