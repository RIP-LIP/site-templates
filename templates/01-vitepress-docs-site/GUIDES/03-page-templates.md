# 03 · 页面结构与内容类型

六类页面，每类给出**结构顺序**和**每个位置该写什么类型的内容**。

对应骨架文件在 `docs/` 下，每个骨架页顶部的注释会指回本文档。

---

## 快速索引

| 页面类型 | 骨架文件 | 何时使用 |
| --- | --- | --- |
| 首页 | `docs/index.md` | 站点唯一的一页 |
| 概念页 | `docs/guide/intro.md` | 「写在开头」「总览」「是什么」 |
| 实操页 | `docs/guide/chapter-1.md` | 上手篇的每一章 |
| 场景页 | `docs/howto/scenario-1.md` | 场景篇的每一篇 |
| 索引页 | `docs/howto/index.md` | 每段的入口总览 |
| 速查表 | `docs/reference/cheatsheet.md` | 参考篇 |

## 一、首页

结构：**Hero → 六宫格 → Markdown 正文 → 页脚**

### Hero

| 位置 | 内容类型 | 写法要求 |
| --- | --- | --- |
| `name` | 品牌短词 | 3~8 字符，英文或拼音，会做渐变填充 |
| `text` | 价值主张 | **说结果，不说功能**。「5 分钟接上你的日程」不是「支持日历集成」 |
| `tagline` | 展开说明 | 一句话讲「新手多久能上手」+「老手能拿到什么」 |
| `image` | 站点图标 | 用 `public/` 里的 SVG，不用位图 |
| `actions` | 行动按钮 | **brand 样式只放一个**，alt 最多两个 |

### 六宫格

每格三件套：

| 字段 | 内容类型 | 反例 → 正例 |
| --- | --- | --- |
| `title` | 读者的处境或目标，2~4 字 | 「功能强大」→「装起来」 |
| `details` | 点进去能**拿到什么**，一句话 | 「包含 XX 模块」→「从零到跑通需 3 步，每步产出什么」 |
| `link` | 通往深处的具体页面 | 指向段首页，不是站外链接 |
| `linkText` | 动作词 | 「了解详情」→「打开上手篇」 |

**六宫格不是「我们有什么」，是「读者现在卡在哪 → 点这里能脱困」。**

### Markdown 正文区

| 小节 | 内容类型 | 说明 |
| --- | --- | --- |
| 这个站解决什么 | 一段话 + 读者画像列表 | 用处境描述读者，不用功能描述自己 |
| 内容结构 | 章节总表 | 必须带「状态」列：✅ 完成 / 🚧 进行中 / ⬜ 未开始 |
| 能做些什么 | 场景矩阵 | **必须带「值得做吗」列**，不能只列功能 |
| 更新记录 | 日期倒序列表 | 一行只说一件事 |

## 二、概念页

结构：**主张 → 不划算的部分 → 对照表 → 关键判断 → 分层方案 → 边界 → 下一步**

| 位置 | 内容类型 | 硬要求 |
| --- | --- | --- |
| H1 | 一句话主张 | 说清「是什么」+「和最像它的东西差在哪」 |
| 引用块 | 写给零基础读者的一句话 | 用「A 给你 X，B 给你 Y」的对立结构 |
| 第 1 段 | 具体事实或场景 | **带数字/名字/日期**，禁「众所周知」「不言而喻」 |
| 先说不划算的部分 | 局限与退出成本 | 必须有。主动写这段能建立信任 |
| 对照表 | 「他们以为」vs「实际上是」 | 至少 4 行 |
| 加粗独立判断句 | 什么时候选 A 什么时候选 B | 全页最可能被截图转发的部分 |
| 分层方案 | 2~3 种做法 | 每种都写「适合」和「不适合」 |
| 边界清单 | 动手前必须想清的事 | 4 条左右，每条给具体建议 |
| 路怎么走 | 编号列表 | 每条写「读完能做什么」，用列表不用表格 |
| 接下来三步 | 可立刻核对的前置条件 | 最后一节必须指向具体的某一章 |

**每个 H2 后面必须跟一张表或一段加粗判断句，不能只有散文。**

## 三、实操页

结构：**目标 → 前置 → 操作 → 验证 → 日常 → 排障 → 下一步**

| 位置 | 内容类型 | 硬要求 |
| --- | --- | --- |
| H1 | 动作导向的标题 | 「装 Docker 引擎」不是「Docker 介绍」 |
| 引用块 | 本章目标 | 写明做完手上会多出什么，**带时间预期** |
| 前置条件 | **可执行的核对命令** | 禁「需要 Python」→ 给 `python --version` |
| 资源表 | 最低 / 建议 | 2~3 行 |
| 操作步骤 | 命令 + 「你应该看到什么」 | 每条命令后必须回答怎么确认成功 |
| 验证 | 逐条检查 | 与安装步骤同等重要，不能省 |
| 日常操作表 | 命令 / 作用 / **是否改动数据** | 破坏性命令标 ⚠️ |
| 常见问题 | Q&A | 答案用「先…再…」写顺序 |
| 跑完之后 | 回到主视角 + 链到下一章 | 必须带链接 |

### 提示框的四种类型，不要混用

| 语法 | 用于 | 例子 |
| --- | --- | --- |
| `::: tip` | 选型建议、经验 | 「默认选方案二，因为…」 |
| `::: warning` | 会丢失数据的操作 | 「这步会删掉所有容器…」 |
| `::: danger` | 权限提升、安全风险 | 「这等价于 root 权限」 |
| `::: info` | 补充背景 | 版本差异、上游变更 |

## 四、场景页

结构：**适用情况 → 跑通后得到什么 → 方案选型 → 先手动 → 再自动化 → 失败告警 → 常见问题 → 再往下做**

| 位置 | 内容类型 | 硬要求 |
| --- | --- | --- |
| H1 | **读者的处境** | 「自动备份到异地」不是「restic 教程」 |
| 引用块 | 谁 / 什么处境 / 卡在哪 | 写成读者心里的话，不是产品话术 |
| 开头段 | 划定范围 | 这篇只做一件事 + 怎么再扩展 |
| 跑通后你会得到什么 | **可验证的输出样例** | 必须和最后一节实际输出格式一致 |
| 方案选型 | 对比表 + **默认推荐** | 说清为什么推荐它 |
| 装上 | 安装命令 | 跨平台给多个命令 |
| **先手动跑一次** | 试跑 → 真跑 → 验证恢复 | **绝不跳过**。手动不通就自动化，失败时无法定位 |
| 配置自动执行 | 定时任务配置 | 单独一节，附容易踩的坑 |
| **加失败告警** | 告警配置 + 验证它在跑 | **最容易被跳过、也最不能跳过** |
| 常见问题 | Q&A | 至少一条是「怎么确认这真有用」 |
| 再往下做 | 进阶方向 | 链到速查表 |

---

## 五、索引页

结构：**一句话说明 → 按处境检索表 → 建议顺序 → 前提条件 → 全量表**

| 位置 | 内容类型 | 说明 |
| --- | --- | --- |
| 开头 | 一段话 | 这页覆盖什么，和别的篇目什么关系 |
| 按你的处境找 | 检索表 | **每行都用读者口吻**，不出现内部术语 |
| 建议的使用顺序 | 编号列表 | 附理由，读者最需要「先做哪个」 |
| 共同前提 | 警告框 | 没满足就别往下做 |
| 全部场景 | 全量表 | 带难度列 |

## 六、速查表

结构：**按用途分组 → 补充表（退出码/错误对照）→ 一个够用的排查顺序**

| 分组类型 | 说明 |
| --- | --- |
| 日常 | 只读查看类命令 |
| 创建/修改 | 会改变系统状态的命令 |
| 清理 | 破坏性命令，**必须标 ⚠️** |
| 诊断 | 排查用命令，通常是流水线 |

末尾放一张**顺序表**：把所有诊断命令串成一条可复制的流水线，这是速查表里最常被单独复制的部分。

## 七、骨架页的标注约定

骨架文件里三种标注，含义不同：

```markdown
## 1. 【操作步骤标题，用动词开头】
<!-- 类型：步骤标题 -->
【正文里每条命令后面跟一句「你应该看到什么」。】
```

| 标注 | 含义 | 处理方式 |
| --- | --- | --- |
| `## 【...】` | 该位置的结构说明 | 保留或改写成你自己的 |
| `<!-- 类型：xxx -->` | **该位置该写什么类型的内容** | 写完后删掉这行 |
| `【...】` | 示例文字 | 整段替换 |

`<!-- 类型：xxx -->` 是填写指引的依据。写完内容后删掉，避免发布出去。

## 八、页面长度

| 页面类型 | 建议长度 | 超过后 |
| --- | --- | --- |
| 首页正文区 | 60 行内 | 删掉「能做些什么」，或移到独立页 |
| 概念页 | 80~150 行 | 拆成两页 |
| 实操页 | 100~200 行 | 拆成两章 |
| 场景页 | 80~150 行 | 场景本身太大，说明该拆成两个场景 |
| 速查表 | 60 行内 | 拆成多张速查表 |

判断标准不是行数，是**读者能否一次读完一个 H2 区块而不需要回滚**。一个 H2 区块超过一屏就该考虑拆。
