# 04 · 内容写作规范

结构在 `GUIDES/03` 讲，这份讲**怎么写**。

---

## 一、六条硬纪律

### 1. 标题说人话，不说功能

| 反例 | 正例 |
| --- | --- |
| 用户认证模块 | 登录与身份验证 |
| 快速开始 | 5 分钟跑通第一个服务 |
| 最佳实践 | 出错了先查这三样 |
| 概述 | 这个东西是什么，和最像它的东西差在哪 |

判断标准：**读者扫一眼标题能不能决定要不要点开。**

### 2. 开头第一句给具体事实

禁用的开头：众所周知 / 不言而喻 / 随着……的发展 / 在当今时代。

替代写法：具体场景、具体数字、具体日期、反直觉的事实。

> 对照：❌「随着 AI 技术的发展」→「✏ 2026 年初，X 两个月斩获 Y 万星标」

具体感是可信度的唯一来源。

### 3. 主动讲缺点

每个方案、每个推荐都要有一节「什么情况下不该用它」。读者会自己发现，你先说反而建立信任。

**过度承诺的代价是不可逆的**：读者按你写的做，踩到坑之后不会再回来。

### 4. 每条命令都说明它会改动什么

速查表必须带「是否改动数据」列；正文里破坏性命令用 ⚠️ 标记并单独警告。

读者复制命令时不会读完整篇文档，**那行标注是他唯一的判断依据**。

### 5. 排障只给顺序，不给零散技巧

```markdown
**Q1：容器状态显示 Exited (1)？**

按这个顺序查，不要跳步：
1. docker compose ps -a        ← 看退出码
2. docker compose logs --tail=50 <服务>
3. docker compose config       ← 配置能否解析
```

散落的「小技巧」读者用不上，因为他不知道现在该用哪条。**顺序本身就是知识。**

### 6. 时效性数据必须标日期，且能删

带具体数字的内容（版本号、星标数、市场份额、日期）**必然过期**。

处理方式：
- 写具体日期：`[2026-03-10]` 而不是「最近」
- 能删就删：教程站没必要写「项目已有 24 万星标」
- 无法删的，在该节末尾加一行：`_最后核对：2026-10-02_`

## 二、句子层面

| 项 | 做法 | 反例 |
| --- | --- | --- |
| 主语 | 用「你」指读者，用「它」指工具 | 「用户可通过该接口进行配置」 |
| 动词 | 用具体动词 | 「进行了优化」→「减少了 3 步」 |
| 长度 | 单句 ≤ 40 字 | 三层从句套一句话 |
| 语气 | 平实，陈述 | 「不得不说」「震惊的是」 |

技术文档里第一人称「我」要慎用，只在「我实测过」这种有实证的地方用。

## 三、表格怎么用

表格是本模板密度最高的排版元素，用好了能省掉大段文字。

| 该用表格 | 不该用表格 |
| --- | --- |
| 三个以上并列选项的对比 | 两个选项（用列表） |
| 配置项 / 参数 / 命令的说明 | 需要展开解释的长段落 |
| 步骤清单 | 需要按顺序执行的操作 |
| 状态、难度、时间预估 | — |

**每张表必须有表头行，且第一列是读者用来定位的维度**（名称、步骤、用途），不是内部编号。

## 四、代码块

| 规则 | 原因 |
| --- | --- |
| 语言标注必写 | 没标注会退化成纯文本，无法高亮 |
| 一段只放一类内容 | 混着放读者不知道哪条能直接复制 |
| 关键参数写在注释里 | 读者不用跳上去看原文 |
| 不写「运行结果」的伪代码 | 除非真的在展示输出格式 |

**最容易犯的错：把模板语法写进代码块导致构建失败。** 见下一节。

---

## 五、模板语法陷阱

VitePress 页面在 markdown 转换后仍会走 Vue 模板编译。**正文任何位置的连续双花括号 `{{ }}` 都会被当成 Vue 插值**，包括反引号包裹的行内代码。

症状：

```
[vite:vue] docs/appendix/appendix-a.md (24:44):
Error parsing JavaScript expression: Unexpected token (1:1)
```

报错信息完全不会提示「你写的双花括号被当成插值」。

### 触发场景

写以下内容时必然中招：

- Docker：`docker inspect -f '{{.State.ExitCode}}'`
- Go template：`{{ .Name }}`
- Handlebars / Jinja / Django 模板
- Vue、Angular 模板示例

### 正解

用 `<span v-pre>` 包住，代码改写成真 HTML（`<` `>` 需转义）：

```markdown
| <span v-pre><code>docker inspect -f '{{.State.ExitCode}}' &lt;容器&gt;</code></span> | 看退出码 |
```

**注意**：code span 内写 `&#123;` 实体不会被解码，会原样显示成 `&#123;`，所以只能走 `v-pre`。

### 预防

写完 markdown 后扫一遍：

```bash
grep -rn '{{' docs --include=*.md
```

命中的位置逐个判断：是 Vue 插值还是模板语法。是模板语法就包 `v-pre`。

## 六、链接

| 类型 | 写法 |
| --- | --- |
| 站内页面 | `[文字](/guide/intro)` —— **不带 `.html`** |
| 站内锚点 | `[文字](/guide/chapter-1#_5-常见问题)` |
| 站外 | `[文字](https://...)` |
| 标题留空但要图标 | `[](/path)` —— 显示为图标 |

**站内链接一律不带后缀**。`cleanUrls` 一旦改成 `true`，手写的 `.html` 会集体失效。

---

## 七、图片

| 规则 | 原因 |
| --- | --- |
| 必须写 `alt` | 无障碍 + 图片挂了有文字兜底 |
| 重要图配 `<small>` 说明 | 读者知道图在说什么 |
| 外部图片注明来源 | 版权 |
| 能用表格表达就别用图 | 表格可搜索、可复制 |

## 八、修改纪律

写文档时最容易出的问题不是写得不好，是**写得太多**。

发布前删一遍，删掉这三类句子：

1. 「众所周知」「值得注意的是」「不难发现」
2. 重复上文意思的总结段
3. 没有对应动作的展望（「未来我们将持续完善」）

删完之后如果某节空了，说明那节本来就不该存在。
